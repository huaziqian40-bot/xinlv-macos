不要碰：`D:\moodsite\android`（安卓版，另一条线）、`D:\moodsite\web`（心履网页端 +
心履服务端，另一条线）、`D:\phix\*`、`D:\phl-*`。

## 这个产品的定位

心履的桌面客户端：记心情、看日历与徽章、AI 树洞、推荐内容；数据与手机/网页端
通过**两个服务端**同步 —— 心履自己的服务端（`xin-lv.com`）管心情记录，
phix（`phix.ing`）管统一账号、资料对象与跨站免密登录。

## 工程约定（请遵守）

- **注释和提交信息用中文**，并且写**为什么**。
- **网络与耗时操作一律走 `ui/Bg.java`**，绝不在 JavaFX 界面线程上做 I/O。
- **不要在界面上展示技术细节**：用户明确要求过客户端不给用户看服务器地址、密钥、
  同步游标这些内部信息。作者信息、版本号、官网链接是要展示的。
- 更新检查必须**三态分明**：已是最新 / 发现新版本 / **检查失败**；
  **"检查失败"绝不能显示成"已是最新版本"**。
- 打开外链用代码库既有的 `Desktop.browse(URI)`，并带打不开时的兜底提示。
- 单元测试把网络/时间做成**可注入的桩**，纯逻辑单独测，不碰真网络。

## 验收标准

- 改完必须跑 `mvn test`（**两个仓库都要**，当前各 **16 个测试，0 失败**）：
  ```powershell
  $env:JAVA_HOME="C:\Program Files\Java\jdk-17"
  $mvn = "C:\Program Files\JetBrains\IntelliJ IDEA 2026.2.0.1\plugins\maven-plugin\lib\maven3\bin\mvn.cmd"
  cd D:\moodsite\windows; & $mvn test     # 汇总被 -q 藏了就去 target\surefire-reports 看
  cd D:\moodsite\macos;   & $mvn test
  ```
- 新逻辑要带测试，照 `SyncEngineWatchTest` / `UpdaterAboutTest` 的风格写。
- 界面改动本机没法无头点测，**如实说明你验证到什么程度**（编译？单测？还是真看了界面）。
- **不要用"我觉得应该没问题"结题**。跑过、看过、贴出证据再结题。

## 发版流程（需要发版时）

1. 改版本号：`pom.xml` 的 `<version>` **和**平台 Updater 的 `APP_VERSION`
   （两个仓库都要）。
2. Windows：`cmd /c "package.bat < NUL"`（结尾有 `pause`，要喂 NUL）。
3. macOS：在 `D:\moodsite` 下 `python -X utf8 build_macos.py`，
   它会在局域网 Mac 上构建**并把产物拉回 `D:\moodsite\deliver`**。
4. 产物交给统一发布流程，**不要自己直接传服务器**。
5. 推送：两个仓库各自 `git push origin main`。

## 你要交付什么

每个任务结束时，报告里要有：改了哪些文件（两个仓库都要列）、**为什么这么改**、
跑了什么命令、**实际结果是什么**（测试数、失败数、界面验证到什么程度）、
**两个仓库是否已同步一致**、以及**你没验证到的部分**（诚实写出来）。
